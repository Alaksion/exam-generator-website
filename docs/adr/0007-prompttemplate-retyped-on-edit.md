# promptTemplate is retyped in full on every certification edit

`config.promptTemplate` is required on both `POST /v1/certifications` and `PUT /v1/certifications/{id}`, but no read endpoint ever returns it — `PublicCertificationConfig` strips it from every response. This means the Certification management edit form has no prior value to pre-fill: the admin must retype the entire prompt template from scratch every time they edit any field on a certification, or the `PUT` request fails validation.

We chose to show this field blank on edit with an explicit warning, rather than caching the last-typed value in browser storage keyed by certification id. A client-side cache would work on the same browser/device but silently fail (falling back to blank) on any other browser, device, or after clearing storage — which is worse than a consistently blank field, since it creates an intermittent trap rather than an obvious one. The trade-off we accept is that every edit to a certification requires retyping a potentially long prompt template in full, even to change an unrelated field like `name` or `isActive`.
