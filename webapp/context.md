# Web App Project Context

> Baseline reference for the React web app that consumes the `exam-generator` serverless API.

## What this backend does

`exam-generator` is a serverless backend that produces practice certification exams for IT cloud providers (AWS, Azure, GCP). It exposes a public REST API protected by an API key. A separate asynchronous generator worker calls Amazon Bedrock to build each exam question set, stores the canonical JSON in S3, renders a PDF, and marks the exam as ready.

The web app should treat the backend as a black-box service: authenticate with a shared API key, read the catalog of certifications, request exams, poll for completion, and display or download the results.

## Core features available to the web app

### 1. Certification catalog

- Browse the catalog of active certifications.
- View a single certification's metadata (provider, code, name, description, version, and generation config).
- The generation config is public-facing but does **not** include the LLM prompt template.

### 2. Request and track exam generation

- Request a new exam for a selected certification.
- Receive an exam ID immediately; the exam starts in `GENERATING` status.
- Poll the status endpoint until the exam reaches `READY` or `FAILED`.

### 3. Take / review a generated exam

- Once an exam is `READY`, fetch the full canonical JSON (questions, answer options, explanations, references).
- The exam is single-answer multiple-choice only; each question has exactly one correct option.
- Render questions in a quiz UI, track selected answers, score the attempt, and show explanations.

### 4. Download exams

- Once an exam is `READY`, request a time-limited presigned URL for the generated PDF.
- The PDF includes the question set, an answer sheet, and an answer key with explanations.

### 5. Manage generated exams

- List ready exams with filters (provider, certification, status) and cursor-based pagination.
- Delete an exam and its S3 artifacts.

## Domain model

### Certification

A catalog entry describing an exam type that can be generated.

| Field | Description |
| --- | --- |
| `id` | UUID generated by the backend. |
| `provider` | `aws`, `azure`, or `gcp`. |
| `code` | Provider-specific exam code, e.g. `CLF-C02`. |
| `name` | Human-readable title, e.g. `AWS Certified Cloud Practitioner`. |
| `version` | Free-form version metadata, e.g. `v1`. |
| `description` | Short description. |
| `isActive` | Whether the certification appears in public listings. |
| `config.questionCount` | Number of questions per generated exam. |
| `config.difficultyDistribution` | Weights for `easy` / `medium` / `hard` that sum to `1.0`. |
| `config.domains` | Topics the generator may draw from. |
| `config.modelId` | Bedrock model used for generation. |

`provider` and `code` together form a unique identity. Deletion is not supported; set `isActive: false` to hide a certification from the catalog.

### Exam

A generated, immutable practice exam.

| Field | Description |
| --- | --- |
| `id` | UUID generated by the backend. |
| `certificationId` | Reference to the certification that produced this exam. |
| `provider` | Denormalized provider from the certification. |
| `title` | Auto-generated title: `{Certification.name} - Practice Exam {ISO-8601 timestamp}`. |
| `status` | `GENERATING`, `READY`, or `FAILED`. |
| `createdAt` | ISO-8601 timestamp when the request was accepted. |
| `finishedAt` | ISO-8601 timestamp when generation finished; `null` until then. |

The full question payload lives in S3 as JSON. DynamoDB stores only the metadata row. The API returns the full payload through `GET /v1/exams/{id}` once the exam is `READY`.

### Question and AnswerOption

A question belongs to exactly one exam.

| Field | Description |
| --- | --- |
| `id` | UUID. |
| `number` | 1-based position within the exam. |
| `domain` | Topic tag, e.g. `Cloud Concepts`. |
| `difficulty` | `easy`, `medium`, or `hard`. |
| `text` | Question prompt. |
| `options` | Array of answer options. |
| `explanation` | Explanation of the correct answer. |
| `reference` | Optional link to official documentation. |

An answer option has:

| Field | Description |
| --- | --- |
| `id` | UUID. |
| `label` | Display label, e.g. `A`, `B`, `C`, `D`. |
| `text` | Answer text. |
| `isCorrect` | Boolean. Exactly one option per question is `true`. |

## Web app user flows

### Flow 1: Browse and request an exam

1. Call `GET /v1/certifications` to populate a certification picker.
2. User selects a certification and clicks "Generate practice exam".
3. Call `POST /v1/exams` with `{ certificationId }`.
4. Store the returned exam ID and start polling.

### Flow 2: Poll generation status

1. Call `GET /v1/exams/{id}/status` every few seconds.
2. Show a progress UI while `status === "GENERATING"`.
3. If `status === "READY"`, transition to the exam review or download screen.
4. If `status === "FAILED"`, show a retry option (allow the user to request a new exam).

### Flow 3: Take an exam

1. Call `GET /v1/exams/{id}` to load the full question set.
2. Render questions one by one or in a paginated view.
3. Track selected answers locally.
4. On submission, compare against `isCorrect` flags and display the score, explanations, and references.

### Flow 4: Download a PDF

1. Call `GET /v1/exams/{id}/download` once the exam is `READY`.
2. Use the presigned `downloadUrl` to redirect the browser or trigger a file download.
3. The URL expires after a short window (default 5 minutes), so fetch it on user action rather than caching it.

### Flow 5: Manage past exams

1. Call `GET /v1/exams` with filters to populate a history list.
2. Use `cursor.nextCursor` and `cursor.hasNextPage` to implement infinite scroll or paginated navigation.
3. Allow deletion via `DELETE /v1/exams/{id}`.

## Authentication and authorization

- No user authentication or sessions.
- Every request must include the `x-api-key` header configured at deployment time.
- The API key is shared by the entire web app (not per-user).
- Rate limiting is enforced by API Gateway throttling and WAF; the front-end should surface `429` errors gracefully.
- CORS is configured to allow cross-origin requests from the web app's hosted origin.

## Error handling conventions

All API errors return a consistent JSON shape:

```json
{
  "error": "CamelCaseErrorCode",
  "message": "Human-readable description"
}
```

Common codes the web app should handle:

| Code | Status | When it happens |
| --- | --- | --- |
| `InvalidRequest` | 400 | Missing or malformed body/query parameters. |
| `NotFound` | 404 | Certification or exam does not exist. |
| `ExamNotFound` | 404 | Exam-specific lookup failed. |
| `ExamNotReady` | 409 | Exam exists but is still `GENERATING` or `FAILED`. |
| `Conflict` | 409 | Duplicate certification provider+code, or invalid state transition. |
| `RateLimitExceeded` | 429 | WAF rate limit exceeded. |
| `InternalError` | 500 | Unexpected server error. |

## Constraints and out-of-scope items

- The MVP supports only single-answer multiple-choice questions.
- Exam titles are auto-generated; the client cannot override them.
- `FAILED` exams cannot be retried; the user must request a new exam.
- There is no user-specific data, no progress persistence on the backend, and no analytics APIs.
- The prompt template is internal and never returned to the client.
- PDF generation is done by the backend; the web app only downloads the presigned file.
